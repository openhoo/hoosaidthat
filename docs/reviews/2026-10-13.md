## Qualification boundaries

The native checks run Linux/amd64 Chromium and real HooVDA/Orca inside OCI
containers on a macOS arm64 host. They verify actual captured reader output.
They do not establish physical Windows/NVDA parity. That qualification requires
the separate Linux/KVM Windows reference VM and its pinned oracle workflow.
The installed CLI's controlled macOS diagnostic and test collection can be
checked here; physical Windows input and NVDA presentation hooks cannot.

The review record names the action cell and settings cells actually run. It
does not treat one 190-action cell as all 760 locale/layout action combinations.
The hosted release workflow was inspected and strengthened locally; it was not
executed or published as part of this task.

A concurrent companion task changed the Go builder base after image
qualification, from the pinned `golang:1.27-bookworm` image to the pinned
`golang:1.27.2-bookworm` image. That edit is preserved. The completed native
results apply to the exact image IDs above; they do not qualify a subsequent
build from the changed companion recipe. `native-parity-summary.json`,
`companion-recipe-drift.json` and `qualification-metadata.json` retain the
build-log identity and observed later source state.
